# ЧҮКӨ v20.39 — PixiJS + Matter.js

Текущая стабильная версия моментальной игры **ЧҮКӨ** для X2 LOTO.

Игра построена так, чтобы:
- результат и денежный выигрыш определялись только LMS;
- PixiJS отвечал за визуальную сцену;
- Matter.js отвечал за физику;
- интерфейс, игровое поле и ассеты можно было менять независимо;
- DEMO и REAL работали через один интерфейс;
- визуальные сценарии были вынесены в отдельный конфиг.

---

# 1. Технологии

Используются:

- **PixiJS 8.20.1** — рендер игрового поля, САКА, чүкө, ХАН, эффектов;
- **Matter.js 0.20.0** — физика удара, столкновений и разлёта;
- **HTML / CSS / JavaScript** — UI;
- **localStorage** — локальные пользовательские настройки и последние билеты;
- **LMS adapter** — баланс, покупка билета, денежный результат, режим REAL.

CDN:
- основной — jsDelivr;
- резервный — unpkg.

---

# 2. Архитектура сцены

Слои:

1. `bg-layer` — фон страницы;
2. `Pixi fieldLayer` — игровое поле;
3. `Pixi pieceLayer` — САКА, чүкө, ХАН;
4. `Pixi outLayer` — выбитые элементы, которые уже вышли из круга;
5. `Pixi fxLayer` — траектория, вспышки, салют;
6. `ui-layer` — весь HTML-интерфейс.

UI не зашит в фоновую картинку.

# 4. LMS — источник истины

В REAL:

- frontend не выбирает выигрыш;
- frontend не рассчитывает денежный результат;
- frontend не создаёт номер билета;
- LMS возвращает:
  - `ticketId`;
  - `scenario`;
  - `win`;
  - `balance`;
  - `denomination`;
  - валюту / язык.

Игра только визуализирует полученный сценарий.

События:

- `X2_GAME_READY`
- `X2_GAME_BALANCE_LOADED`
- `X2_GAME_DENOMINATION_CHANGED`
- `X2_GAME_TICKET_READY`
- `X2_GAME_ROUND_COMPLETE`
- `X2_GAME_DEPOSIT_REQUEST`
- `X2_GAME_MODE_CHANGED`
- `X2_GAME_HELP_REQUEST`
- `X2_GAME_ERROR`

# 5. REAL / DEMO

Поддерживаются режимы:

- `REAL`
- `DEMO`

REAL:
- запрос билета отправляется в LMS;
- ставка списывается LMS;
- выигрыш приходит от LMS;
- баланс обновляется из LMS.

DEMO:
- использует виртуальный баланс;
- реальные деньги не затрагиваются;
- сценарии автоматически берутся из `scenario-config.js`;
- DEMO проходит по списку сценариев циклически.

---

# 6. Сценарии

Все сценарии находятся в:

`src/scenario-config.js`

Сценарий описывает только визуальный результат:

```js
{
  id: 1,
  key: 'ZERO',
  regular: 0,
  khan: false,
  demoMultiplier: 0
}
```

Поля:
- `regular` — сколько обычных чүкө выбито;
- `khan` — выбит ли ХАН;
- `demoMultiplier` — используется только MOCK / DEMO.

REAL `win` всегда приходит от LMS.

DEMO-порядок задаётся через:

```js
demoOrder
```

# 7. Физика

САКА:

- можно потянуть вниз и отпустить;
- используется drag/pull-логика из принятой версии v20.1;
- максимальное оттягивание — 115 px design-space;
- выбранное направление показывается пунктирной линией;
- после удара САКА получает отскок.

Чүкө:

- вся куча реагирует на удар;
- невыигрышные элементы двигаются и сталкиваются внутри круга;
- только выбранные LMS-сценарием элементы могут выйти за границу;
- у каждого выбитого чүкө своя дальность вылета;
- после полного выхода он фиксируется в `outLayer`;
- после фиксации он больше не возвращается и не двигается;
- остаётся на месте до следующей `Новой игры`.

ХАН:

- участвует в общем ударе;
- если сценарий выигрышный, начинает движение одновременно с чүкө;
- не ждёт отдельного delayed launch;
- поддерживается минимальная наружная скорость;
- после выхода фиксируется в `outLayer`.

# 10. Номиналы

Верхний выпадающий список удалён.

Номиналы показываются кнопками под основными кнопками.

Особенности:

- значения выводятся без валюты;
- активный номинал подсвечивается;
- игрок может выбирать только номиналы, переданные LMS;
- если значения не помещаются в одну строку, появляются стрелки прокрутки;
- в REAL выбранный номинал отправляется в запросе на новый билет.

# 11. Автоигра

Кнопка находится рядом с `Новая игра`.

Количество игр задаётся в:

`config.js`

```js
autoPlayCounts: [5, 10, 20, 50]
```

UX:

1. нажать `Автоигра`;
2. выбрать количество;
3. кнопка меняется на `Старт 10`;
4. автоигра начинается только после нажатия `Старт 10`;
5. во время серии показывается, например:
   `Стоп 3/10`.

В REAL автоигра сама:
- отправляет запрос нового билета;
- ждёт ответ LMS;
- выполняет бросок;
- завершает визуализацию;
- после завершения текущего раунда запрашивает следующий билет.

При `Стоп`:
- текущий уже купленный / начатый раунд завершается;
- новые билеты больше не покупаются.

# 12. Автоигра и эффекты

Начиная с v20.39 следующий раунд автоигры **не обрывает эффект выигрыша**.

Правила:

- `0` — короткая пауза;
- обычный выигрыш — ждём полного окончания конфетти;
- ХАН — ждём полного окончания конфетти и салюта;
- только после этого запрашивается следующий билет.

Настройки:

`src/visual-config.js → tuning.effects.autoPlay`

```js
autoPlay: {
  waitForCelebration: true,
  endPaddingMs: 180,
  zeroHoldMs: 900
}
```

Длительность ожидания рассчитывается автоматически из текущих настроек эффектов.

# 15. Мои билеты

`Инфо → Мои билеты`

Локально показываются последние завершённые билеты.

Хранятся только:

```js
{
  ticketId,
  win
}
```

Лимит:

`config.js`

```js
localTicketHistoryLimit: 5
```

Можно установить, например:

```js
localTicketHistoryLimit: 10
```

Правила:

- запись создаётся только после завершения раунда;
- новый билет сверху;
- дубликаты по `ticketId` не сохраняются;
- REAL и DEMO хранятся отдельно;
- номер билета показывается полностью;
- справа показывается только сумма выигрыша;
- слово `Выигрыш` в каждой строке не выводится.

Это только локальный удобный список.

Полная история остаётся в личном кабинете LMS.

# 18. Отображение результата

Старая центральная плашка `Выигрыш` удалена.

Теперь:

- показывается только сумма;
- без слова `Выигрыш`;
- без валюты;
- сумма появляется крупной цифрой;
- результат не показывается до завершения визуального раунда.

Пример:


# 21. Салют ХАНА

Для выигрыша с выбитым ХАНОМ запускается PixiJS-салют.

Салют:

1. ракета стартует снизу;
2. летит вверх;
3. имеет хвост;
4. происходит вспышка;
5. десятки частиц разлетаются радиально;
6. частицы замедляются;
7. затем падают под условной гравитацией.

Настройки:

`src/visual-config.js → tuning.effects.fireworks`

```js
fireworks: {
  enabled: true,
  count: 3,
  particlesPerBurst: 54,
  rocketDurationMs: 620,
  burstDurationMs: 1450,
  gravity: 0.055,
  spread: 1.0,
  rocketHeightMin: 330,
  rocketHeightMax: 520
}
```

# 22. Безопасность Pixi-эффектов в автоигре

С v20.38 эффекты результата имеют отдельный lifecycle.

При старте нового раунда:

1. сначала отключаются callbacks эффекта из Pixi ticker;
2. отменяются delayed timeouts;
3. только потом уничтожается Pixi-графика.

Это предотвращает зависание физики при автоигре.

# 23. Результат в нижних карточках

Карточки:

```text
ВЫБИТО — ХАН — ВЫИГРЫШ
```

`ВЫИГРЫШ`:
- показывает только сумму;
- без валюты;
- до завершения броска показывает `0`.

`ХАН`:
- `×5`, если ХАН выбит;
- `УСТОЯЛ`, если раунд завершён без выбивания;
- `—`, пока результат ещё не визуализирован.

# 28. Важные правила разработки

При дальнейших изменениях:

1. Не менять drag/pull САКА без отдельной задачи.
2. `bindPointer()` считается эталонным от v20.1.
3. Не рассчитывать выигрыш во frontend.
4. Не выбирать сценарий во frontend в REAL.
5. Не менять LMS adapter при чисто визуальных задачах.
6. Выбитые элементы должны оставаться на месте до `Новая игра`.
7. Новая автоигра не должна обрывать праздничный эффект.
8. Все основные визуальные параметры по возможности выносить в `visual-config.js`.
9. Все сценарии держать в `scenario-config.js`.
10. Старые рабочие версии не перезаписывать.
